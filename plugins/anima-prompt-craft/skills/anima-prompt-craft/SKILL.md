# Anima Prompt Craft

Anima（circlestone-labs）向けに、コピペで動くプロンプトと生成設定を作るスキル。

**設計方針**：判断が必要な手順だけ SKILL.md に置き、公式仕様の全量は `references/` に分離する。

- `references/official-spec.md` … 公式モデルカードの要点（バージョン差・生成設定・タグ体系・データセットタグ・制限・学習・ライセンス）
- `references/recipes.md` … 用途別テンプレート、完成例、症状別トラブルシュート

---

## 0. 最初にやること

1. **バージョンを確認する**（Base / Aesthetic / Turbo）。品質タグとCFG・ステップが変わるので、ここを外すと全部ズレる。
   - 不明なら **Turbo を仮定**して、末尾で「どのバージョンか」を一言確認する（公式も入門は Turbo 推奨）。
2. 迷う点があれば `references/official-spec.md` を読む。**タグ順序・データセットタグ・LoRA学習・ライセンス**の話が出たら必ず読む。
3. 用途別テンプレや「思った絵にならない」相談は `references/recipes.md` を読む。

| バージョン | 品質タグ | ステップ / CFG | 性格 |
| --- | --- | --- | --- |
| Base | 使う（`score_*` も可） | 30〜50 / 4〜5 | 素体。多様性・画風追従が最大、既定は地味 |
| Aesthetic | `masterpiece, best quality` まで。**`score_*` はポジ・ネガ両方で使わない** | 30〜50 / 4〜5 | 既定の画風が綺麗。安定寄り |
| Turbo | Base と同様に使える | **8〜12 / CFG 1** | 高速・安定。多様性は落ちる |

> `score_*` を Aesthetic に入れると品質側へ押し込みすぎて「slop」化する。ここは公式が明示している数少ない禁止事項。

## 1. プロンプトの組み立て（公式のタグ順序）

```
[品質 / メタ / 年代 / 安全タグ] [1girl・1boy・1other 等] [character] [series] [@artist] [一般タグ]
```

各セクション内は順不同でよい。セクションの**順番だけ**守る。

**基本ルール**

- タグは**小文字・スペース区切り**。アンダースコアを使うのは `score_7` のようなスコアタグだけ
- Danbooru と Gelbooru でタグ名が違うときは **Gelbooru 版**を採用
- アーティストは **`@` を必ず前置**（`@artist name`）。@ が無いと効果が激弱になる
- 強調構文は使えるが、**SDXL より強い重みが必要**（例：`(chibi:2)`）。SDXL の `1.2` 感覚だとほぼ効かない
- タグドロップアウト学習済み → 関連タグを全部並べる必要はない。**盛りすぎない**

**推奨の出発点**（Base / Turbo）

- ポジ接頭：`masterpiece, best quality, score_7, safe, `
- ネガ：`worst quality, low quality, score_1, score_2, score_3, artist name, blurry, jpeg artifacts, chromatic aberration`

---

## 2. タグと自然文の混ぜ方（Anima の強み）

Anima は「Danbooruタグ」「自然文キャプション」「その混合」で学習されている。混ぜて書けるのが SDXL 系との最大の違い。

- **任意の順で混在可**。品質タグ・@アーティストを自然文の頭に置いてもよい
  - 例：`masterpiece, best quality, @artist name. An anime girl with medium-length blonde hair is ...`
- 純自然文で書くなら**2文以上・具体的に**。極端に短いと結果が不安定になる
- キャラ名・シリーズ名は**英語の標準的な大文字ルール**に従う（`Fern from Sousou no Frieren`）
- **キャラ名 → 外見描写**の順で書く。名前だけ並べると、特に複数キャラで混ざる
  - 既存キャラでない（Danbooru に無い）キャラは character / series タグが存在しないので、**一般タグ＋自然文で外見を描写して作る**

---

## 3. 意図しない内容を防ぐ

短い・薄いプロンプトほど、望まない内容が出やすいモデル。対策は2つセットで行う。

- **安全タグを明示**：ポジに `safe`（または `sensitive`）、ネガに `nsfw, explicit`
- **記述量を確保**：衣装・ポーズ・背景・ライティングを具体的に書く

安全タグは `safe` / `sensitive` / `nsfw` / `explicit` の4段階。全年齢向けなら `safe` を基本にする。

必ずこの形で出す。説明は最小限、コピペしやすさ最優先。

````
## ポジティブプロンプト

```
（ポジティブ）
```

## ネガティブプロンプト

```
（ネガティブ）
```

## 生成設定

- バージョン: Anima-Turbo / Aesthetic / Base
- 解像度: 1024x1024（等）
- ステップ / CFG: 8-12 / 1（Turbo）または 30-50 / 4-5
- サンプラー: er_sde（等）
````

**生成設定の既定値**

- 解像度：**512² 〜 1536²** の範囲で動く（1024x1024 / 896x1152 / 1152x896 あたりが扱いやすい）
- サンプラー：`er_sde` を既定に。柔らかく細い線なら `euler_a`（CFGを少し高めにしても焼けにくい）、多様性を出したいなら `dpmpp_2m_sde_gpu`（暴れることあり）、Turbo/Aesthetic には `euler` も good
- 絵画・厚塗り寄りにしたいときは `beta57` スケジューラ（RES4LYF カスタムノード）

## 5. 作成ワークフロー

「○○のプロンプトを作って」と言われたら：

1. **バージョン判定**（§0）→ 品質タグとステップ/CFGを確定
2. **テーマ分解**：被写体／シーン（場所・時間・季節）／衣装／ポーズ・表情／ライティング／カメラ
3. **タグ順序どおりに配置**（§1）。既存キャラなら `character` → `series`、オリキャラなら一般タグで描写
4. **自然文を1〜2文添える**（§2）。特にオリキャラ・複数キャラ・複雑な構図のとき
5. **安全タグをポジ・ネガ両方に**（§3）
6. **チェック**：小文字か／アンダースコアはスコアタグだけか／@は付いてるか／Aestheticに`score_*`を入れていないか／タグを盛りすぎていないか／写実を要求していないか
7. **§4のフォーマットで出力**（生成設定まで書く）

## 6. このモデルで無理なこと（先に伝える）

- **写実は出ない**（意図的にアニメ／イラスト／非写実特化）。フォトリアル要求が来たら、この時点で別モデルを勧める
- **長い文字の描画は苦手**。単語〜短いフレーズが限界
- **Base は素体**。アーティストタグ・品質タグ無しだと地味でニュートラルな絵になる
- アニメ知識の学習データは **2025年9月**まで。それ以降のキャラ・作品は知らない

## 7. ライセンスの注意（商用まわり）

以下は要点の要約。正式な判断は必ず `references/official-spec.md` に載せた公式ライセンス原文の要約と、可能であれば一次情報を確認すること。

- **モデル本体は非商用ライセンス**（CircleStone Labs Non-Commercial License ＋ NVIDIA Open Model License）
- **出力画像（Outputs）は制限の対象外＝商用利用OK**。画像の販売・有償コミッション・有料プロダクトの素材利用は可
- **モデルをAPIで有料提供する／有料生成サービスに載せる／収益化プロダクトに重みを同梱する**には別途商用ライセンスが必要
- ただし、**個人として活動している場合の派生モデル（LoRA等）重みの販売**には個別の除外規定がある。該当しそうな場合は `references/official-spec.md` の第2条c相当の記述を必ず確認する
- 詳細は `references/official-spec.md` の該当節を参照

## 8. 自己改善

この SKILL.md と `references/` はマーケットプレイスの配布物であり、直接編集しない。プラグインが更新されるたびに上書きされ、更新を受け取れなくなるため。

ユーザーから出力への指摘があったら、このスキルを親とする**子スキル**に追記する。

- 子スキルの場所：`~/.claude/skills/anima-prompt-craft-updates/SKILL.md`（無ければ新規作成する）
- 子スキルのフロントマター例：
  ```
  ---
  name: anima-prompt-craft-updates
  description: anima-prompt-craft スキルの追加ルール・更新知見を保持する子スキル。anima-prompt-craft を使う際は必ず一緒に参照する。
  ---
  ```
- 追記する内容は種類ごとに見出しを分ける：
  - **手順・判断・出力形式の知見**
  - **公式仕様の追記・訂正**（新バージョン、設定値の更新など）
  - **テンプレ・完成例・トラブルシュート**
- 追記後、子スキルのどこに何を追記したかを一言で伝える
